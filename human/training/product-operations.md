# 产品运营培养方案
按成长阶段分节，每个阶段写清训练内容、参与方式、验收标志。Issue 用来记录问题与证据，PR 用来验收实际改进。  
阶段一：作为使用者观察体验  训练内容：练观察与描述——先能发现哪里不顺手，再把问题说清楚；不先教固定操作步骤。  参与方式：以普通成员身份使用产品；用 Issue 提交问题，写清现象、复现步骤、影响范围和截图等证据；本阶段不要求提交 PR。  验收标志：能连续提出问题，且每份 Issue 可被他人复现、不需要反复追问；描述里能区分「现象」与「猜测的原因」。  
阶段二：被委派承担运营工作  训练内容：练把问题转成可执行的改进，并验证改进是否生效。  参与方式：接受委派负责一块日常运营；Issue 继续承载问题与证据，PR 承载改进方案、实际改动与验证结果；每个 PR 关联到对应 Issue。  验收标志：有已合并的 PR，且能说明它解决了哪条 Issue、怎么验证的；运营工作能按约定节奏持续交付，而不是等指令才动。  
阶段三：参与机制维护  训练内容：练维护运营机制本身——把重复出现的问题归纳成规则、清单或检查项。  参与方式：用 Issue 记录机制缺口与复盘结论；用 PR 修改运营文档、模板和检查清单；对他人提交的 Issue 与 PR 给出复核意见。  验收标志：机制变更有 PR 可追溯，且其他人按新机制能独立执行；能说明一条规则是从哪几份 Issue 归纳出来的。  
阶段四：与产品、架构协作判断改进  训练内容：练判断优先级与方案取舍，把一线观察带进产品决策。  参与方式：与产品经理、架构师一起评审；用 Issue 汇总证据与影响面，用 PR 提交或配合落实被采纳的改进；在评审记录里写明采纳或不采纳的依据。  验收标志：能提出有证据支撑的改进判断并被采纳或明确驳回，且结论留档；开始承担更完整的责任，而不只是执行分配到的任务。  
Issue 与 PR 的分工  Issue：问题、证据、复现、影响范围、复盘结论；是「发现了什么」的记录。  PR：改进方案、实际改动、验证结果、机制文档变更；是「改了什么、怎么验」的验收凭据。  两者成对出现：一条 PR 至少关联一条 Issue，一条 Issue 若被处理，结论回写到 Issue。  
边界  这是具体实例，不作为统一晋升标准。  提案原文记录的是成员从群成员转为运营、维护机制并发现产品问题的实际成长过程，不能直接视为适合所有人的统一晋升标准。  每个团队的日常运营流程不同，本方案训练的是观察、描述和验证问题的能力，不假定存在一套可迁移的固定步骤。  原始讨论上下文、实践状态与结果表述仍待核对；如有后续数据或制度版本，可补充后再作为成熟案例迁移。
