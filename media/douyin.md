# 抖音图文发布

把已成档案的图文发到抖音。认证与 Playwright 环境复用 [小红书与抖音双平台发布](rednote.md) 的准备步骤，本篇只写抖音与小红书不同的部分。

抖音侧每次发布弹人机验证，本篇按「人机各半」组织：执行器填表，人过验证。

## 与小红书的差异

| 项 | 抖音 | 小红书 |
|------|------|--------|
| 发布入口 | `creator.douyin.com/creator-micro/content/upload` | `creator.xiaohongshu.com/publish/publish` |
| 图文入口 | 顶部「发布图文」tab | 顶部「上传图文」tab |
| 图片 input | 多个 `input[type=file]` 中取 `accept` 含 `image/` 且带 `multiple` 的 | 唯一一个 |
| 标题 | 独立输入框，限 20 字 | 无独立标题，首行即标题 |
| 话题数 | 档案「平台限制」只带后 4 个 | 全部 10 个 |
| 发布按钮 | 标准 `button`，取最后一个 | 非 button 元素，按坐标点底部那颗 |
| 发布凭证 | 跳转作品管理页，内容管理可见 | URL 含 `published=true` |
| 人机验证 | 每次发布弹短信验证码 | 无 |

## 发布步骤

1. 打开发布页 → 点「发布图文」→ 向图片 input 传 9 张图 → 等待跳转 `content/post/image` 表单页。
2. 填标题（20 字内）与描述；描述带门店名称与定位，正文末尾按档案「平台限制」只打抖音的 4 个话题，逐个 `#话题` 后点选下拉项成蓝色。
3. 底部「发布」为唯一含「发布」文本的 button，直接点。
4. **停在验证弹窗，交人**：短信验证码发到账号绑定手机，执行器不代填。人提供验证码后填入点「验证」，或改用「使用原设备扫码」。

## 踩过的坑

- **表单页不跨导航**：发布中重新 goto 上传页，表单与图片全丢。填表与点发布必须放同一次会话，验证弹窗出现后保持会话等待人输入。
- **描述框假丢失**：填长描述后编辑框视觉上像被截断（滚动所致），以字数计数（`n/1000`）与右侧手机预览为准，不要凭编辑框可见部分判断内容缺失。
- **验证超时**：弹窗停留过久会话可能失效，验证失败不要自动重试整条发布链，人确认后再继续。

## 验收标准

```yaml work
work: douyin-tuwen-publish
标题: 抖音图文发布
版本: 1

输入:
  档案: { 必填: true }        # data/profile/create/<店名>.md
  验证码: { 必填: true, 来源: 人 }   # 短信验证码或扫码确认

前置:
  - Playwright Firefox profile 已复制且抖音登录态有效（见 rednote.md）
  - 档案图片清单九张齐备，标题不超 20 字

步骤:
  - 传图: 图文 tab → 图片 input → 9 张 → 等表单页
  - 填表: 标题 + 描述（含门店名称与定位）+ 4 个话题成蓝色
  - 发布: 点底部「发布」→ 停在验证弹窗等人
  - 验证: 人提供验证码或扫码 → 填入点「验证」
  - 凭证: 记录作品链接

验收:
  - 内容管理页可见该作品
  - 标题 ≤20 字，话题恰为档案「平台限制」的 4 个
  - 描述含门店名称与定位
```

## 不做

- 认证与 profile 复用、封面叠字（在[双平台发布](rednote.md)）
- 素材同步与转码（在 [导出 iCloud 照片](../work/export-icloud-photo.md)）
- 视频发布（本篇只覆盖图文）
